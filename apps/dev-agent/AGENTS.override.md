# AGENTS.override.md

## 1. 文档定位

本文件用于约束代理在 `apps/dev-agent/` 目录内工作的方式。

`apps/dev-agent` 是桌面端项目，包含：

- Web 前端界面
- Tauri 宿主层
- 本地资源
- 测试目录
- 与 Agent Core 的本地通信相关逻辑

在本目录内工作时，应优先保证：

1. UI 行为正确
2. 本地通信边界清晰
3. 前端状态管理可理解
4. 不破坏桌面端构建链路
5. 不把底层运行时逻辑错误地下沉或上浮

---

## 2. 模块边界认知

### 2.1 目录职责
主要目录含义如下：

- `src/`：前端业务界面与交互逻辑
- `src-tauri/`：Tauri 宿主层
- `public/`：静态资源
- `test/`：测试
- `dist/`：前端构建产物
- `node_modules/`：依赖目录

### 2.2 边界原则
在本模块内工作时：

- UI 展示与交互逻辑优先留在 `src/`
- Tauri 宿主逻辑优先留在 `src-tauri/`
- Agent Core 的底层运行逻辑不应复制到桌面端项目中
- 本地通信协议应保持边界清晰，不要混淆 UI 事件与底层运行时事件

---

## 3. 工作原则

### 3.1 先判断问题类型
修改前先判断属于：

1. 纯前端页面问题
2. 组件交互问题
3. 状态管理问题
4. Tauri 宿主逻辑问题
5. UI 与 Agent Core 通信问题
6. 构建打包问题

其中第 4、5、6 类默认按中高风险处理。

### 3.2 先复用现有模式
修改 UI 时，优先：

- 复用现有布局
- 复用现有组件模式
- 复用现有状态处理方式
- 优先采用 shadcn/ui 的能力
- 保持页面结构一致性

不要在一个局部需求里引入全新的设计风格或状态管理方式。

### 3.3 不做无关 UI 大改
若任务是修复功能，不要顺手：

- 重写整个页面
- 改全局主题
- 替换现有组件体系
- 调整大面积视觉风格

除非得到明确许可。

---

## 4. 前端 `src/` 规则

### 4.1 状态应可追踪
页面状态、连接状态、错误状态、加载状态必须清晰，不要把关键状态隐藏在零散副作用里。

### 4.2 管理界面优先强调信息清晰
桌面端若涉及：

- 连接状态
- 重连按钮
- 延迟展示
- 日志状态
- 隧道/服务列表
- Agent 运行状态

优先保证：

1. 状态含义明确
2. 错误可理解
3. 加载与空状态明确
4. 操作反馈及时

### 4.3 API / IPC 规则
若前端通过命令调用、事件、IPC 或本地接口与宿主/Agent 通信：

- 不要臆造字段
- 不要静默吞掉错误
- 不要在前端重复实现底层状态机
- 需要明确失败时的 UI 表现

---

## 5. `src-tauri/` 规则

### 5.1 宿主层属于高敏感区
修改 `src-tauri/` 时，必须关注：

- 命令边界
- 权限与安全
- 本地进程调用
- IPC/事件桥接
- 生命周期
- 异常退出处理

### 5.2 与 Agent Core 通信时的要求
若涉及 Tauri 与 Agent Core 通信逻辑，必须说明：

1. 通信方式是什么
2. 消息边界是什么
3. 错误如何传回 UI
4. 是否影响已有本地协议
5. 是否需要同步修改 Agent Core

### 5.3 不把复杂业务堆在宿主层
宿主层主要负责：

- 通道桥接
- 权限控制
- 命令转发
- 资源访问

不要把大段业务编排和复杂状态决策堆在 `src-tauri/`。

---

## 6. 构建与依赖规则

### 6.1 不直接修改构建产物和依赖目录
默认不要直接修改：

- `dist/`
- `node_modules/`

### 6.2 构建相关文件修改要谨慎
涉及以下文件时，必须明确说明影响范围：

- `package.json`
- `vite.config.ts`
- `tsconfig.json`
- `tsconfig.node.json`
- `tailwind.config.ts`
- `postcss.config.cjs`
- `components.json`

### 6.3 变更脚本前先看现状
若涉及 npm scripts、构建脚本或测试脚本，必须先依据 `package.json` 现有内容处理，不要凭空假设脚本存在。

---

## 7. 测试与验证规则

### 7.1 前端验证优先级
通常优先考虑：

1. 类型检查
2. lint
3. 测试
4. build

前提是对应脚本在 `package.json` 中真实存在。

### 7.2 Tauri 相关改动
若改了 `src-tauri/` 或桌面端联动逻辑，应特别说明是否验证过：

- 前端调用宿主命令
- 命令返回错误场景
- 本地通信失败场景
- 应用启动/关闭基本流程

### 7.3 未覆盖项必须明说
若没有执行：

- Tauri 真机构建
- 桌面端联调
- Windows/Linux 平台验证
- 与 Agent Core 的真实联调

必须在结果中明确说明。

---

## 8. 文档同步要求

若改动影响以下内容，应考虑同步更新仓库根 `docs/`：

- Agent 与 Tauri 本地通信方案
- UI 设计方案
- Agent 执行清单
- 管理页面交互模型
- 启动与连接模型

---

## 9. 完成任务后的输出要求

至少说明：

1. 修改目标
2. 影响目录
3. 是否涉及前端、Tauri、IPC 或 Agent Core 协同
4. 核心改动
5. 风险点
6. 已执行验证
7. 未执行的桌面端联调或构建验证

---

## 10. 明确禁止的行为

禁止：

- 直接修改 `dist/` 或 `node_modules/`
- 把 Agent Core 底层逻辑复制进前端项目
- 未说明原因就改本地通信协议
- 未考虑错误路径就修改 UI/IPC 交互
- 为修复小问题而整体重写界面结构
